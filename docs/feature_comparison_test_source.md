# 決済端末アプリ 機能仕様書

## 対応決済方法

本アプリケーションは以下の決済方法に対応しています。

### 対応済み決済方法

| 決済方法 | 表示名 | 対応状況 |
|---------|--------|------------|
| CREDIT_CARD | クレジットカード（EMV IC / 磁気） | ✓ 対応 |
| SUICA | Suica（交通系IC） | ✓ 対応 |
| QR_CODE | QR決済（PayPay/LINE Pay等） | ✓ 対応 |
| WAON | WAON | ✓ 対応 |
| NANACO | nanaco | ✓ 対応 |
| RAKUTEN_EDY | 楽天Edy | ✓ 対応 |
| APPLE_PAY | Apple Pay | ✓ 対応 |
| D_PAYMENT | d払い | ✓ 対応 |

### 未対応決済方法

| 決済方法 | 表示名 | 対応状況 |
|---------|--------|------------|
| CASH | 現金支払 | × 未対応 |
| PREPAID | プリペイド（Intent外部連携） | × 未対応 |

## カード読み取り機能

本アプリケーションは、クレジットカード・デビットカード等の読み取り機能を提供します。

### 読み取りモード

| モード | 定数名 | 説明 |
|-------|--------|------|
| ICチップ | IC_CHIP | EMV IC チップ読み取り（PIN認証あり） |
| 磁気ストライプ | MAGNETIC_STRIPE | 磁気カード読み取り（署名確認を要求） |
| 非接触 | CONTACTLESS | タップ決済（上限金額超過時はICチップ読み取りにフォールバック） |

### 読み取り処理

**機能**: `readCard(mode: ReadMode)`

指定されたモードでカード読み取りを実行します。

**ICチップ読み取り**:
- PIN認証が必要
- PIN検証に失敗した場合はエラーを返却
- 成功時はマスク済みカード番号とブランド名を返却

**磁気ストライプ読み取り**:
- 署名確認を要求する運用を想定
- 成功時はマスク済みカード番号とブランド名を返却

**非接触読み取り**:
- 上限金額: 20,000円
- 上限金額を超える場合は自動的にICチップ読み取りにフォールバック
- 上限以内の場合はPIN不要で決済完了

**戻り値**:
- `CardReadResult.Success`: 読み取り成功時、マスク済みカード番号とブランド名を返却
- `CardReadResult.Failure`: 読み取り失敗時、エラー理由を返却

## 割引・クーポン適用機能

本アプリケーションは、複数種類の割引・クーポン・ポイント充当を組み合わせて適用する機能を提供します。

### 割引種別

| 種別 | クラス名 | 優先度（デフォルト） | 重複適用可否 |
|------|---------|---------------------|-------------|
| パーセント割引 | PercentageOff | 1 | 不可 |
| 固定額割引 | FixedAmountOff | 2 | 可 |
| ポイント充当 | PointRedemption | 3 | 可 |

### 割引適用ルール

- 優先度の高い順（降順）に割引を適用
- 重複適用不可（`isStackable = false`）の割引が既に適用されている場合、後続の割引は適用されない
- 割引後の金額が0円未満にならないよう制御（最小値: 0円）

### 割引計算

**機能**: `applyDiscount(originalAmount: Int, discounts: List<Discount>)`

指定された割引リストを元の金額に適用し、最終金額を計算します。

**バリデーション**:
- 元の金額が正の整数であることを確認

**戻り値**:
- `DiscountResult.Success`: 計算成功時、元の金額、最終金額、適用された割引リストを返却
- `DiscountResult.Failure`: 計算失敗時、エラー理由を返却

## 分乗決済機能

本アプリケーションは、複数人で1回の乗車料金を分割して支払う「分乗決済」機能に対応しています。タクシー利用時などで、複数の決済方法を組み合わせて支払うことが可能です。

### 機能概要

- 総額に対して、複数の決済方法で分割支払いが可能
- 各分割に対して、対応済み決済方法のみ利用可能
- 分割金額の合計が総額を超えないよう制御

### 分割支払い登録

**機能**: `addSplit(method: PaymentMethod, amount: Int)`

分割支払いエントリを追加します。

**バリデーション**:
- 指定された決済方法が分乗決済に対応しているか確認
- 分割金額が正の整数であることを確認
- 現在の分割金額合計 + 追加金額が総額を超えないことを確認

**戻り値**:
- `SplitResult.Success`: 分割追加成功時、現在の分割リストを返却
- `SplitResult.Failure`: 分割追加失敗時、エラー理由を返却

### 決済状況確認

**機能**: `isFullySettled()`

分割金額の合計が総額と一致しているかを判定します。

**機能**: `remainingAmount()`

残りの未分割金額を返却します。

### 決済実行

**機能**: `settleAll()`

登録された全ての分割支払いを実行します。各分割エントリに対して決済処理を行い、結果のリストを返却します。

### レシート印字機能

**機能**: `buildReceiptText(splits: List<SplitEntry>, totalAmount: Int)`

分乗決済の利用明細をレシート印字用のテキスト形式で組み立てます。

**出力内容**:
- 合計金額
- 分乗内訳（各決済方法と金額）

**戻り値**:
- レシート印字用のテキスト文字列

## タクシーメーター連携機能

本アプリケーションは、タクシーメーター機器（IM-A820等）との連携機能を提供します。メーターで確定された運賃を受け取り、決済フローに引き渡します。

### 機能概要

- メーターから確定運賃情報を受信
- 運賃情報の妥当性検証
- 決済処理への運賃情報引き渡し

### メーター運賃情報

**データ構造**: `MeterFare`

| フィールド | 型 | 説明 |
|-----------|-----|------|
| amount | Int | 確定運賃額（円） |
| distanceKm | Double | 走行距離（km） |
| waitingTimeMinutes | Int | 待機時間（分） |
| nightSurcharge | Boolean | 深夜割増フラグ |

### 運賃受信処理

**機能**: `onFareFixed(fare: MeterFare)`

メーターから確定した運賃情報を受信します。

**パラメータ**:
- `fare`: メーターから受信した運賃情報

### 運賃取得処理

**機能**: `pullFareForPayment()`

決済処理のために確定運賃情報を取得します。

**バリデーション**:
- メーターから運賃情報が届いていることを確認
- 運賃額が正の整数であることを確認（0円以下は不正として扱う）

**戻り値**:
- `MeterPullResult.Success`: 取得成功時、運賃情報を返却
- `MeterPullResult.Failure`: 取得失敗時、エラー理由を返却
  - "メーターから確定運賃が届いていません" - 運賃情報未受信
  - "運賃額が不正です: {金額}" - 運賃額が0円以下

### 運賃情報クリア

**機能**: `clearFare()`

保持している運賃情報をクリアします。決済完了後などに実行します。

## 前払い決済機能（与信管理）

本アプリケーションは、乗車前にあらかじめ上限額を与信する前払い決済機能を提供します。タクシー版アプリ固有の機能として、実際の運賃確定後に精算を行います。

### 機能概要

- 乗車前に予想運賃額で与信を確保
- 降車時に実際の運賃で精算
- 与信額と実額の差額を返金処理

### 与信確保処理

**機能**: `createHold(customerId: String, estimatedAmount: Int)`

顧客に対して予想運賃額で与信を確保します。

**パラメータ**:
- `customerId`: 顧客識別子
- `estimatedAmount`: 予想運賃額（円）

**バリデーション**:
- 与信額が正の整数であることを確認

**戻り値**:
- `HoldResult.Success`: 与信成功時、顧客IDと与信額を返却
- `HoldResult.Failure`: 与信失敗時、エラー理由を返却
  - "与信額が不正です" - 与信額が0円以下

### 与信精算処理

**機能**: `finalizeHold(customerId: String, actualAmount: Int)`

確定した実際の運賃で与信を精算します。

**パラメータ**:
- `customerId`: 顧客識別子
- `actualAmount`: 実際の運賃額（円）

**バリデーション**:
- 該当顧客の与信情報が存在することを確認
- 実際の運賃が与信額以内であることを確認

**戻り値**:
- `FinalizeResult.Success`: 精算成功時、顧客ID、確定額、返金額を返却
  - `finalAmount`: 確定した運賃額
  - `refundAmount`: 返金額（与信額 - 実際の運賃額）
- `FinalizeResult.Failure`: 精算失敗時、エラー理由を返却
  - "与信情報が見つかりません: {顧客ID}" - 与信情報未登録
  - "実際の運賃が与信額を超えています（与信: {与信額}, 実額: {実額}）" - 運賃超過

## 商品スキャン機能（POS版）

本アプリケーションは、GS1-128バーコードによる商品スキャン機能を提供します。POS版アプリにおいて、商品マスタ連携とカート追加フローを実現します。

### 機能概要

- GS1-128形式のバーコード読み取り
- 商品マスタとの照合
- 商品情報と数量の取得

### バーコードスキャン処理

**機能**: `scan(rawBarcode: String)`

バーコード文字列を解析し、商品マスタと照合して商品情報を返却します。

**パラメータ**:
- `rawBarcode`: 読み取ったバーコード文字列

**バリデーション**:
- GS1-128形式（AI識別子"01"で始まる、16文字以上）であることを確認
- 商品マスタに該当SKUが登録されていることを確認

**処理フロー**:
1. バーコード形式の検証
2. AI（アプリケーション識別子）ごとにSKUと数量をパース
3. 商品マスタから商品情報を検索
4. 商品情報と数量を返却

**戻り値**:
- `ScanResult.Success`: スキャン成功時、商品情報と数量を返却
- `ScanResult.Failure`: スキャン失敗時、エラー理由を返却
  - "バーコード形式が不正です: {バーコード}" - GS1-128形式不正
  - "商品マスタに登録されていません: {SKU}" - 商品未登録

**備考**:
- max_tokens拡大後の再検証に対応

### 商品マスタ管理

**クラス**: `ProductCatalog`

商品マスタの管理と動的同期を提供します。

**データ構造**: `Product`

| フィールド | 型 | 説明 |
|-----------|-----|------|
| sku | String | 商品コード（SKU） |
| name | String | 商品名 |
| price | Int | 販売価格（円） |
| taxRate | Int | 消費税率（%） |

**機能**: `findBySku(sku: String)`

SKUから商品情報を検索します。

**機能**: `upsert(product: Product)`

商品情報を登録または更新します。

**機能**: `syncFromServer(remoteProducts: List<Product>)`

サーバー側の商品マスタと同期します。

**戻り値**: `SyncSummary`
- `added`: 新規追加された商品数
- `updated`: 更新された商品数
- `totalCount`: 同期後の総商品数

## 取引履歴管理機能

本アプリケーションは、取引履歴の記録・検索・オフライン同期機能を提供します。通信断時にローカルへ一時保存し、後で同期する運用に対応しています。

### 機能概要

- 取引の記録と管理
- 取引IDによる検索
- 未同期取引の管理
- 日次サマリーの生成

### 取引記録

**機能**: `record(method: PaymentMethod, amount: Int, status: TransactionStatus)`

決済取引を記録します。

**パラメータ**:
- `method`: 決済方法
- `amount`: 決済金額（円）
- `status`: 取引ステータス

**戻り値**:
- `TransactionRecord`: 記録された取引情報（一意なID付き）

### 取引検索

**機能**: `findById(id: String)`

取引IDから取引情報を検索します。

**戻り値**:
- 該当する取引情報、または該当なしの場合は`null`

### 未同期取引取得

**機能**: `unsyncedTransactions()`

サーバーへ未同期の取引一覧を取得します。

**戻り値**:
- 未同期取引のリスト

### 同期マーク設定

**機能**: `markSynced(id: String)`

指定された取引を同期済みとしてマークします。

**戻り値**:
- 成功時は`true`、該当取引が存在しない場合は`false`

### 日次サマリー生成

**機能**: `dailySummary()`

本日の取引サマリーを生成します。

**戻り値**: `DailySummary`
- `totalAmount`: 合計金額
- `transactionCount`: 取引件数

### 取引ステータス

| ステータス | 説明 |

## 返金処理機能

本アプリケーションは、取消・返品処理による返金機能を提供します。当日取消（オーソリ取消）と、日をまたいだ返金（再与信）を分けて扱います。

### 機能概要

- 完了済み取引の返金処理
- 当日取消と再与信返金の自動判定
- 返金理由の記録

### 返金処理

**機能**: `refund(transactionId: String, reason: RefundReason)`

指定された取引に対して返金処理を実行します。

**パラメータ**:
- `transactionId`: 取引ID
- `reason`: 返金理由

**バリデーション**:
- 該当取引が存在することを確認
- 取引ステータスが完了済みであることを確認

**処理フロー**:
- 当日中の取引: オーソリ取消で対応
- 日をまたいだ取引: 再与信返金で対応
- 現金決済の場合: 日をまたいだ返金は窓口対応が必要

**戻り値**:
- `RefundResult.Success`: 返金成功時、取引ID、金額、返金方法、理由を返却
- `RefundResult.Failure`: 返金失敗時、エラー理由を返却

### 返金理由

| 理由 | 説明 |
|------|------|
| CUSTOMER_REQUEST | 顧客からの依頼 |
| SYSTEM_ERROR | システムエラー |
| DUPLICATE_CHARGE | 二重請求 |
| OTHER | その他 |

## 日次締め処理機能

本アプリケーションは、日次バッチ精算機能を提供します。端末内に溜まった取引をまとめてセンターへ送信し、売上を確定させます。

### 機能概要

- 本日の取引サマリー生成
- 未同期取引のセンター送信
- 部分的な失敗のハンドリング

### バッチ処理実行

**機能**: `runDailyBatch()`

日次締め処理を実行します。

**処理フロー**:
1. 本日の取引サマリーを生成
2. 未同期取引を取得
3. 各取引をセンターへ送信
4. 成功した取引に同期済みマークを設定
5. 処理結果を返却

**戻り値**:
- `BatchResult.Success`: 全取引の同期に成功した場合
- `BatchResult.PartialFailure`: 一部の取引同期に失敗した場合
- `BatchResult.NoOp`: 本日の取引が存在しない場合

## ハードウェア監視機能

本アプリケーションは、決済端末のハードウェア状態を監視する機能を提供します。バッテリー、プリンター用紙、通信状況などの状態確認に対応しています。

### 機能概要

- バッテリー残量の監視
- プリンター用紙残量の監視
- ネットワーク接続状態の監視
- カードリーダー接続状態の確認

### ハードウェア状態取得

**機能**: `checkStatus()`

現在のハードウェア状態を取得します。

**戻り値**: `HardwareStatus`
- `batteryLevel`: バッテリー残量（%）
- `printerPaperRemaining`: プリンター用紙状態
- `networkStatus`: ネットワーク接続状態

### バッテリー警告判定

**機能**: `shouldWarnLowBattery(status: HardwareStatus)`

バッテリー残量が警告レベル（20%）を下回っているか判定します。

**戻り値**:
- 警告が必要な場合は`true`

### 用紙警告判定

**機能**: `shouldWarnLowPaper(status: HardwareStatus)`

プリンター用紙が少量または切れているか判定します。

**戻り値**:
- 警告が必要な場合は`true`

### プリンター用紙状態

| 状態 | 説明 |
|------|------|
| OK | 正常 |
| LOW | 残量少 |

### ネットワーク状態

| 状態 | 説明 |
|------|------|
| ONLINE | オンライン |
| OFFLINE | オフライン |

**備考**:
- オフライン時は取引ログに一時保存し、復旧後に自動同期する運用を想定
