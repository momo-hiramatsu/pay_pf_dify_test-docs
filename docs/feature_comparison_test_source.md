# 決済端末アプリ 機能仕様書

## 対応決済方法

本アプリケーションは以下の決済方法に対応しています。

### 対応済み決済方法

| 決済方法 | 表示名 | 対応状況 |
|---------|--------|------------|
| CREDIT_CARD | クレジットカード（EMV IC / 磁気） | ✓ 対応 |
| SUICA | Suica（交通系IC） | ✓ 対応 |
| QR_CODE | QR決済（PayPay/LINE Pay等） | ✓ 対応 |
| WAON | WAON | ✓ 対応 |
| NANACO | nanaco | ✓ 対応 |
| RAKUTEN_EDY | 楽天Edy | ✓ 対応 |
| APPLE_PAY | Apple Pay | ✓ 対応 |

### 未対応決済方法

| 決済方法 | 表示名 | 対応状況 |
|---------|--------|------------|
| CASH | 現金支払 | × 未対応 |
| PREPAID | プリペイド（Intent外部連携） | × 未対応 |

## カード読み取り機能

本アプリケーションは、クレジットカード・デビットカード等の読み取り機能を提供します。

### 読み取りモード

| モード | 定数名 | 説明 |
|-------|--------|------|
| ICチップ | IC_CHIP | EMV IC チップ読み取り（PIN認証あり） |
| 磁気ストライプ | MAGNETIC_STRIPE | 磁気カード読み取り（署名確認を要求） |
| 非接触 | CONTACTLESS | タップ決済（上限金額超過時はICチップ読み取りにフォールバック） |

### 読み取り処理

**機能**: `readCard(mode: ReadMode)`

指定されたモードでカード読み取りを実行します。

**ICチップ読み取り**:
- PIN認証が必要
- PIN検証に失敗した場合はエラーを返却
- 成功時はマスク済みカード番号とブランド名を返却

**磁気ストライプ読み取り**:
- 署名確認を要求する運用を想定
- 成功時はマスク済みカード番号とブランド名を返却

**非接触読み取り**:
- 上限金額: 20,000円
- 上限金額を超える場合は自動的にICチップ読み取りにフォールバック
- 上限以内の場合はPIN不要で決済完了

**戻り値**:
- `CardReadResult.Success`: 読み取り成功時、マスク済みカード番号とブランド名を返却
- `CardReadResult.Failure`: 読み取り失敗時、エラー理由を返却

## 割引・クーポン適用機能

本アプリケーションは、複数種類の割引・クーポン・ポイント充当を組み合わせて適用する機能を提供します。

### 割引種別

| 種別 | クラス名 | 優先度（デフォルト） | 重複適用可否 |
|------|---------|---------------------|-------------|
| パーセント割引 | PercentageOff | 1 | 不可 |
| 固定額割引 | FixedAmountOff | 2 | 可 |
| ポイント充当 | PointRedemption | 3 | 可 |

### 割引適用ルール

- 優先度の高い順（降順）に割引を適用
- 重複適用不可（`isStackable = false`）の割引が既に適用されている場合、後続の割引は適用されない
- 割引後の金額が0円未満にならないよう制御（最小値: 0円）

### 割引計算

**機能**: `applyDiscount(originalAmount: Int, discounts: List<Discount>)`

指定された割引リストを元の金額に適用し、最終金額を計算します。

**バリデーション**:
- 元の金額が正の整数であることを確認

**戻り値**:
- `DiscountResult.Success`: 計算成功時、元の金額、最終金額、適用された割引リストを返却
- `DiscountResult.Failure`: 計算失敗時、エラー理由を返却

## 分乗決済機能

本アプリケーションは、複数人で1回の乗車料金を分割して支払う「分乗決済」機能に対応しています。タクシー利用時などで、複数の決済方法を組み合わせて支払うことが可能です。

### 機能概要

- 総額に対して、複数の決済方法で分割支払いが可能
- 各分割に対して、対応済み決済方法のみ利用可能
- 分割金額の合計が総額を超えないよう制御

### 分割支払い登録

**機能**: `addSplit(method: PaymentMethod, amount: Int)`

分割支払いエントリを追加します。

**バリデーション**:
- 指定された決済方法が分乗決済に対応しているか確認
- 分割金額が正の整数であることを確認
- 現在の分割金額合計 + 追加金額が総額を超えないことを確認

**戻り値**:
- `SplitResult.Success`: 分割追加成功時、現在の分割リストを返却
- `SplitResult.Failure`: 分割追加失敗時、エラー理由を返却

### 決済状況確認

**機能**: `isFullySettled()`

分割金額の合計が総額と一致しているかを判定します。

**機能**: `remainingAmount()`

残りの未分割金額を返却します。

### 決済実行

**機能**: `settleAll()`

登録された全ての分割支払いを実行します。各分割エントリに対して決済処理を行い、結果のリストを返却します。

## タクシーメーター連携機能

本アプリケーションは、タクシーメーター機器（IM-A820等）との連携機能を提供します。メーターで確定された運賃を受け取り、決済フローに引き渡します。

### 機能概要

- メーターから確定運賃情報を受信
- 運賃情報の妥当性検証
- 決済処理への運賃情報引き渡し

### メーター運賃情報

**データ構造**: `MeterFare`

| フィールド | 型 | 説明 |
|-----------|-----|------|
| amount | Int | 確定運賃額（円） |
| distanceKm | Double | 走行距離（km） |
| waitingTimeMinutes | Int | 待機時間（分） |
| nightSurcharge | Boolean | 深夜割増フラグ |

### 運賃受信処理

**機能**: `onFareFixed(fare: MeterFare)`

メーターから確定した運賃情報を受信します。

**パラメータ**:
- `fare`: メーターから受信した運賃情報

### 運賃取得処理

**機能**: `pullFareForPayment()`

決済処理のために確定運賃情報を取得します。

**バリデーション**:
- メーターから運賃情報が届いていることを確認
- 運賃額が正の整数であることを確認（0円以下は不正として扱う）

**戻り値**:
- `MeterPullResult.Success`: 取得成功時、運賃情報を返却
- `MeterPullResult.Failure`: 取得失敗時、エラー理由を返却
  - "メーターから確定運賃が届いていません" - 運賃情報未受信
  - "運賃額が不正です: {金額}" - 運賃額が0円以下

### 運賃情報クリア

**機能**: `clearFare()`

保持している運賃情報をクリアします。決済完了後などに実行します。

## 前払い決済機能（与信管理）

本アプリケーションは、乗車前にあらかじめ上限額を与信する前払い決済機能を提供します。タクシー版アプリ固有の機能として、実際の運賃確定後に精算を行います。

### 機能概要

- 乗車前に予想運賃額で与信を確保
- 降車時に実際の運賃で精算
- 与信額と実額の差額を返金処理

### 与信確保処理

**機能**: `createHold(customerId: String, estimatedAmount: Int)`

顧客に対して予想運賃額で与信を確保します。

**パラメータ**:
- `customerId`: 顧客識別子
- `estimatedAmount`: 予想運賃額（円）

**バリデーション**:
- 与信額が正の整数であることを確認

**戻り値**:
- `HoldResult.Success`: 与信成功時、顧客IDと与信額を返却
- `HoldResult.Failure`: 与信失敗時、エラー理由を返却
  - "与信額が不正です" - 与信額が0円以下

### 与信精算処理

**機能**: `finalizeHold(customerId: String, actualAmount: Int)`

確定した実際の運賃で与信を精算します。

**パラメータ**:
- `customerId`: 顧客識別子
- `actualAmount`: 実際の運賃額（円）

**バリデーション**:
- 該当顧客の与信情報が存在することを確認
- 実際の運賃が与信額以内であることを確認

**戻り値**:
- `FinalizeResult.Success`: 精算成功時、顧客ID、確定額、返金額を返却
  - `finalAmount`: 確定した運賃額
  - `refundAmount`: 返金額（与信額 - 実際の運賃額）
- `FinalizeResult.Failure`: 精算失敗時、エラー理由を返却
  - "与信情報が見つかりません: {顧客ID}" - 与信情報未登録
  - "実際の運賃が与信額を超えています（与信: {与信額}, 実額: {実額}）" - 運賃超過
